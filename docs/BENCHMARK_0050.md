# 0050 對決 — 誰比較強

## 0. 先講結論

**以目前 repo 裡真實的回測資料判斷：0050 比較強。**

這個結論不需要新的資料就能下，因為 `data/backtests/rotation_v0.4.json` 已經有真實的五年結果：

| | 五年總報酬 | MaxDD | 贏過大盤的年數 |
|---|---:|---:|---:|
| v0.4 rotation（fixed 20/20） | +185.48% | **-59.09%** | 2 / 6 |
| TAIEX 價格指數 | +161.92% | — | — |
| TAIEX + 3.5%/年股息（0050 的合理近似） | **+211.07%** | 約 -30% | — |

三件事同時成立：

1. **含息之後策略輸了。** 185.48% < 211.07%。策略只贏「不含息的價格指數」，而價格指數不是任何人可以買的東西。
2. **風險差一個量級。** -59.09% vs 約 -30%。同樣的報酬區間，回撤是兩倍。
3. **時間分布極度不健康。** 2022、2023、2024、2025 連續四年輸給大盤，總報酬完全靠 2026 的 +180% 拉起來。

> 逐年超額：2021 +7.47%、2022 -7.70%、2023 **-38.37%**、2024 **-32.33%**、2025 **-19.18%**、2026 +126.27%

一個要贏 0050 的策略，不能只在某一年贏很多，其他年份都在流血。

## 1. 為什麼會輸：成本，不是訊號

台股買賣一趟的成本是固定的：

```
買進手續費 0.1425% + 賣出手續費 0.1425% + 證券交易稅 0.3% = 0.585%
```

這個數字會複利侵蝕本金：

| 交易次數 | 累積成本侵蝕 |
|---:|---:|
| 12 | 6.80% |
| 24 | 13.13% |
| 60 | 29.67% |
| 155 | 59.72% |
| 235 | 74.81% |
| 466 | 93.50% |

換句話說，**在五年內做 150 次交易，等於還沒開始賺就先輸掉六成的投入資金**。10 日動能在六個類股之間的排序每天都在洗牌，任何「排名變了就換股」的規則都會踩進這個陷阱。

這在本次開發過程中被實際踩到：core-satellite 的第一版沒有遲滯機制，五年做了 **466 筆交易、其中 465 筆是持有一天的來回**，把 -2.54% 的 benchmark 打成 -67.67%。這不是參數問題，是規則設計問題。

## 2. Core-satellite：為了贏 0050 而設計的架構

`coreSatellite.js`。核心想法一句話：**預設持倉就是 0050，只有真的有訊號時才偏離。**

帳戶分成 K 個 slot：

- 有合格類股時，該 slot 持有類股籃子（satellite）
- 沒有時，該 slot 持有 0050（core）

因此策略永遠 100% 在市場裡，不會像 v0.4 那樣在多頭裡空手。**完全沒有訊號時，這個策略在數學上等於 0050 買進持有** —— 測試以 1e-9 精度驗證總報酬相等、beta = 1.000、tracking error = 0。下檔因此相對 0050 有界，超額只能來自真的有訊號的時段。

### 控制 turnover 的四個機制

| 參數 | 作用 |
|---|---|
| `exitRankBuffer` | 遲滯帶：排名進入前 K 才買，要掉出 K + buffer 才賣。避免排名微幅洗牌就換股 |
| `minHoldingDays` | 最短持有天數，排名理由不能在此之前出場（停損停利不受限） |
| `rebalanceEvery` | 排名相關的換股只在再平衡日執行；風控出場仍每日判斷 |
| `cooldownDays` | 停損／停利後，該類股冷卻 N 天不得買回，消除 v0.4 出場隔天原地重進的來回費用 |

| 參數 | 作用 |
|---|---|
| `maxSatelliteSlots` | 最多幾個 slot 可以偏離 0050，直接控制 tracking error 上限 |
| `benchmarkDividendYield` | 股息同時計入 benchmark 與策略的 core 部位，任何一邊都不能靠股息假設佔便宜 |

### 衡量方式也換掉了

只看總報酬不足以宣稱「贏了 0050」。`benchmarkComparison` 產出：

- 超額報酬、beta、年化 alpha
- tracking error、information ratio
- 上漲/下跌捕獲率（up / down capture）
- **滾動一年勝率**：隨機挑一天進場，一年後贏 0050 的機率
- 最差滾動一年超額
- `costsPaid`：實際付給券商與國庫的金額，佔初始資金的比例

滾動一年勝率是最誠實的一欄。總報酬贏 0050 但滾動勝率只有 40%，代表大多數進場時點其實是輸的。

## 3. 目前還沒有真實數字

`scripts/runBenchmarkBattle.js` 已經可以完整執行：72 個 core-satellite 設定 × 4 種股息假設 ×（完整視窗 + 前後半段 + 逐年），並套用 v0.5 的 robustness gate。

但**這份報告的真實數字尚未產生**。開發環境的 network egress 只允許 GitHub，`www.twse.com.tw`、Yahoo Finance、FinMind 全部被擋，因此拿不到 0050 的真實價格。本次只用合成資料驗證程式路徑。

合成資料**不能**用來判斷策略好壞：它是帶 regime 漂移的隨機漫步，橫斷面動能在建構上就沒有真實 edge，所以合成結果既不能證明策略有用，也不能證明沒用。合成產出的報告刻意沒有 commit。

要拿到真實答案，執行 `Benchmark Battle vs 0050` workflow（或本機 `npm run battle:0050`），它會寫出 `data/backtests/benchmark_battle_0050.{json,md}`。

### 屆時該怎麼判讀

按這個順序看，任何一關沒過就是 0050 贏：

1. **含息比較**：在 3.5% 股息假設下超額是否為正？只在 0% 股息假設下贏不算贏。
2. **風險調整**：Calmar 是否高於 0050？報酬贏但回撤兩倍不算贏。
3. **滾動一年勝率**：是否顯著高於 50%？
4. **逐年分布**：是否只靠單一年份？v0.4 就是敗在這一關。
5. **Robustness gate**：鄰近參數是否也能用？（v0.5 的 family gate）

## 4. 限制

- Universe 仍是 curated 的六類股 / 十八檔，hindsight-selection 風險不變。
- 0050 使用未還原股息的收盤價，股息以年化率近似累積，不是逐筆除息還原；四種股息假設的敏感度分析就是為了界定這個近似的影響。
- 類股籃子同樣未計股息。若籃子殖利率明顯高於 0050，這裡會低估策略。
- 沒有計入滑價與流動性衝擊，只計入手續費與證交稅。
- 一段五年視窗仍然只是一個樣本。
- 研究用途，不構成投資建議。
